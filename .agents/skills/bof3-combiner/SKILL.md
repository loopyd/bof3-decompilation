# BOF3 combiner

1. Bind the caller's target, selected functions, paths and mission limits. Read the
   [target contract](../bof3-re/references/target-contract.md) and shared
   [editing and recovery](../bof3-re/references/editing-recovery.md) rules.
2. Inspect `bin/harness combiner list TARGET --json`, complete source bodies and
   current effective compiler settings. Calls, shared types/macros and storage
   relationships are leads. Choose a coherent operation or subsystem whose grouping
   improves navigation and removes repeated declarations or unnecessary files.
   Explain a no-op when the proposed grouping adds no useful clarity.
3. Establish complete selected membership from target claims, attached metadata,
   maps and every reviewed Splat boundary. Include all functions in each writable
   source. Preserve independent target ownership, full original ranges, external
   bindings, initialized-data placement and required BSS evidence. Missing identity,
   unsupported placement or unresolved consumers block acceptance.
4. Capture owned PRE, including deleted sources, absent destinations, metadata,
   manifest, layout and any authorized compiler configuration change. Preserve the
   adopted dirty work and index. Record live native PRE and every source's effective
   compiler/ordered flags. A common profile must survive movement; attached per-
   function settings may express it. Conflicting profiles require a separately
   evidenced decision, never silently dropping path-specific settings.
5. Edit authorized files directly. Keep every complete metadata block attached to
   its definition or standalone macro invocation under the
   [metadata rules](../bof3-re/references/metadata.md). Preserve spellings/order
   unless independently justified. Migrate
   source/header/support claims and Splat C markers together, and remove obsolete
   files and callers. Retain all distinct source bodies and private declarations.
   Check declaration visibility, static-name collisions, include order, initialization,
   aliasing and volatile behavior across the whole resulting translation unit.
6. Run `bin/harness combiner check TARGET SELECTOR...` and required live asm-diff
   and byte-match gates. Grouped native checks compile the complete current source
   and compare every member and reviewed initialized-data section. Check all affected
   callers and owning targets. Compilation, one matching member or a percentage
   does not establish preservation. Follow
   [native execution](../bof3-re/references/native-execution.md) for resource bounds.
7. Obtain independent review of grouping value, complete member/consumer scope,
   behavior, ABI, ranges, profiles and bindings. Record progress only through the
   [metadata owner](../bof3-re/references/metadata.md) after the live gate, then
   recheck the edited records. Separate scoped success from campaign completion.

After failed comparison or review, confirm writer termination and restore only
owned PRE, including deleted files and original absence states. Preserve unrelated
work and raw index state. Verify restoration before another writer. Uncertain
cleanup stops mutation and retains PRE, POST and actual process handles. No
transaction, ranking or recovery script is required. Frozen campaign membership,
partial-result constraints, attempt limits and unfinished duties remain binding.

For path-only batches, follow
[source relocation](../bof3-naming/references/source-relocation.md) for shallow
source/include placement, build regeneration and empty-directory pruning.
