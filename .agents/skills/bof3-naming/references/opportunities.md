# Naming opportunities

```sh
bin/harness naming opportunities TARGET
bin/harness naming describe-opportunity TARGET ID --expected-fingerprint PIN
bin/harness agent context cleanup naming-opportunity TARGET ID
```

Discover raw functions/data through read-only target maps. Do not open/refresh the
index or mutate reports, source or maps. Invalid/missing maps fail; they do not
prove exhaustion. Preserve exact spellings/suffixes. Inventory covers raw debt,
not all improvable names, shared symbols or representations.

`bof3.naming-opportunity/v1` row: `id` as `TARGET@KIND:NAME`, `target`, `kind`,
`name`, actual mapped `address`, repo-relative `map`, `map_sha256`, `fingerprint`.
Fingerprint is `v1:` SHA-256 compact sorted-key JSON over other fields. Functions
then data by name, deterministic enumeration not semantic-value ranking/top-N.

Retain target/ID/fingerprint externally. Description requires current membership;
the expected pin rejects row/map drift. Scout only when unpinned. Any map byte
change invalidates leads; never silently repin. Non-atomic observation binds only
the map. Success proves no downstream freshness, useful name or evidence closure
and grants no mutation authority.

Open/unavailable access evidence blocks conclusions despite positive capability
facts. Opportunity assessment cannot claim unfiltered `complete:true`. Keep audit,
evidenced proposal, identity approval, native verification and rollback separate.
Preserve frozen requests/receipts through skill-path migrations. Missing canonical
report prerequisites block; never run `init-all` over retained history.

## Mission method

Use actual mission limits, not unvalidated historical three-row/70-call heuristics.
Calibrate against accepted units, evidence/review coverage and partial results.
Serialize report writers; stop on a held lock. Probe consequential premises before
delegation. Keep unsupported rows blocked with the smallest missing fact and one
bounded next command.

Match reviewer tools to required checks. Distinguish supplied evidence from actual
execution; unavailable required gates remain open. Compare against the starting
dirty snapshot, not mtime or whole HEAD diff; report attribution limits if absent.
Distinguish a weakened gate from insufficient evidence. Require independent acceptance.

Function ownership needs proven reviewed range/payload containment; data uses
map/load/layout and consumers, not empty function-owner results. Foreign spelling
is only lead until shared-map/recursive proof. Synthesized probe/receipt/replay flag
is not canonical run: payload, checkpoint and report-derived operation plan must
agree. Inspect owner failure evidence before attributing a failure to the harness.
Reproduce Rizin in the actual invocation
mode; standalone `-c` and live stdin interactive flags differ.
