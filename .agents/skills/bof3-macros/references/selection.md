# Macro selection

Use `bin/harness macros list TARGET --kind KIND` to inspect definitions, lexical
uses, repeated C tokens/statements or normalized original-byte intervals. Help
lists current kinds. A limit changes presentation only. A stale index requires
an explicit refresh at a safe checkpoint. Listing never refreshes it.

Prefer coherent operations with meaningful parameters, clear calls, reduced
repetition and maintainable definitions. Inspect C89, original instructions and
existing macros before selecting. Incidental similarity is insufficient. Preserve
useful abstractions and generated bindings. Discovery supplies no write authority.

For template extraction, require at least four useful disjoint uses. Frozen
campaigns retain their selected members, instruction floor, ordering, budgets,
prior failures and unfinished duties. Current lexical repetition can appear with
fewer occurrences; that is a lead, not extraction acceptance. Native instruction
repeats retain opcode/register fields and branch displacements, parameterizing
only explicit immediate/address fields. They do not prove C equivalence, source
mapping, liveness or safe transfer/delay-slot context.

Review each proposed argument and every current use for evaluation count, side
effects, integer promotions and conversions, precedence, lvalue behavior,
volatility, aliasing and control flow. Resolve each hazard with evidence or an
explicit reason it does not apply. Byte equality alone cannot establish future
argument safety or readability. Keep fixed-address bindings, pointer-cell and
pointee qualifiers and actual register/frame effects intact.

Lexical use names do not prove expansion binding. Inspect include order,
conditional definitions, `#undef`, token pasting, computed names and unindexed
inputs with the actual preprocessor and source context. Resolve unknown bindings
before editing. Preserve shared ownership and target-local addresses, maps,
wrappers and declarations. Shared bodies must be address-free.
