# Existing abstractions

Inspect the current definition and every affected use under
[selection](selection.md) and [application](application.md). If the macro already
names a coherent operation with clear parameters and call sites, keep it. Explain
why no edit improves it. Review current semantic hazards and native consumers when
claiming current acceptance.

A no-op does not count as a new extraction or reconstruct missing private proofs.
Shared promotion still requires independently exact private wrappers and every
consumer. A stale result, ambiguous expansion or missing native gate remains
unresolved. Preserve frozen campaign membership and unfinished obligations in the
owning task, without manufacturing a replacement abstraction or accounting ledger.

## Lane handoff

A lift lane hands an exact body here before it is named, because a merge changes
the form the name is written in: the identifier becomes the invocation's
function argument and one invocation can emit a different symbol set.

Decide from `bin/harness macros list TARGET --kind definitions|uses|byte-repeats`
and `bin/harness macros check TARGET SELECTOR`. A match requires equal emitted
instructions, equal index width, equal cell identities and equal statement order
against an existing exact user. A near miss is `no-match` with the measured
difference, not a stretched definition.

Applying an existing macro's invocation is the lane's whole authority here: keep
the metadata block above it, re-gate every affected selector at 100%, and take the
wave reviewer's acceptance. A new macro, a shared-definition edit or a
cross-target extraction is a candidate for the parent, never a lane merge.
