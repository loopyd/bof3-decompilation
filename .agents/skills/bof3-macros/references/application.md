# Macro application

Read [selection](selection.md) and shared
[editing and recovery](../../bof3-re/references/editing-recovery.md) before edits.
Capture owned PRE and the adopted dirty/index baseline, then establish current
native results. Edit the smallest useful extraction directly.

Resolve all direct and transitive consumers of the definition, including other
parameters and uses outside the selected repetition. Inspect the complete writable
files. A grouped source requires all attached ordinary functions and reviewed
Splat members, even when a member lacks metadata. An unidentified use or sibling
cannot substitute for a checked consumer. Keep every member's address, range,
metadata, declaration and binding intact.

Use effective compiler settings and literal dependencies, including `-include`
and `-imacros`, to establish actual definition binding. Quoted includes search the
including directory first; angle includes do not. Missing, escaping or unsupported
inputs block acceptance. Conditional lexical matches require preprocessor review.

A new private header requires explicit scope, an unused target-owned path and a
manifest header claim. Preserve absent PRE, include resolution and all other
manifest facts. Check every new header consumer. For shared promotion, first
establish independently reviewed exact private wrappers in at least two owning
targets with identical semantic and parameter contracts. Check every wrapper and
shared consumer; representatives do not cover omitted functions.

Run the current macro check and complete original-range byte gates. Preserve exacts
and unselected partials under the shared recovery rules. Obtain independent review
of semantic hazards, parameter mapping, all use sites and human value. Only then
record selected progress through the metadata owner and recheck it. Keep failed,
unavailable and unreviewed results separate from accepted cleanup.

After failure or cancellation, terminate owned native writers before restoring
only owned PRE. Retain evidence and stop mutation if cleanup or identity-safe
restoration is uncertain. Historical receipts remain evidence; they do not require
an executable transaction protocol.
