# Text tool refinement

Read the [tooling contract](../../bof3-re/references/tooling-contract.md) before
harness or skill script edits. Read the
[target contract](../../bof3-re/references/target-contract.md) before target work.
Route native evidence through [psx-rizin](../../psx-rizin/SKILL.md) and runtime
observations through [psx-emulator](../../psx-emulator/SKILL.md).

## Close a source gap

Start from an unresolved coverage range and the actual US bytes. Identify its
loader and consumer, string addressing, encoding, boundaries, commands and any
shared or indirect references. Record addresses and byte ranges sufficient to
reproduce each conclusion. Executable, overlay, menu, name and description text
remain part of the full objective even when the known-bank export passes.

Pass raw Rizin inputs as absolute paths. The managed tool runs from its executable
directory.

A `textbin` target entry describes raw data in a code section. Its name does not
establish that those bytes are strings. Scanner quality, vocabulary agreement,
frequency and a plausible decoded preview are leads. Promotion requires consumer
evidence and original-byte reproduction.

Implement only the layout the evidence supports. Keep codecs and format logic in
Rust; the Python harness forwards arguments. Preserve existing classified-window
barriers and report unresolved bytes. Use the existing payload inventory and
reviewed target records rather than a second exclusion policy. Every range must
remain known text, evidenced nontext, or unresolved.

For writes, bind documents to original archive bytes and identify every reference
before supporting relocation. Preserve bytes outside authorized allocations and
refuse unsupported growth. Migrate affected callers and documentation; remove
superseded parsers and paths.

## Verify and report

Run the existing Rust checks, affected harness checks, documentation drift and the
repository's shared gate. Use disposable outputs to check deterministic coverage,
mutation detection, full known-bank round trips, capacity refusal, shared-row
consistency, stale provenance and source preservation. New regression tests require
the user's explicit request under this repository's rules.

Retain run evidence in ignored `out/` and task state in the owning OpenSpec change.
Keep maintained documentation about supported behavior and lasting limits.
Review completed, hash-checked captures. If edited bytes reach RAM but the display
does not change, trace the draw call and its source before accepting that consumer.
Another bank or a graphical label remains a possibility, not an established cause.
Acceptance must reconcile the full US source inventory with byte verification and
observed consumers. Record regional support separately. Leave unresolved source,
reference, encoding and runtime gates open until their evidence exists.
