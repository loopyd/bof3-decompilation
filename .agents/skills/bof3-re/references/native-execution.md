# Native execution

## Authority and profile

Autonomous parent has standing authority for bounded index/analysis refreshes,
independent reviews, native compile/compare gates and accepted feature-completion
commits. No push/release, install, policy weakening or retry after denial. Ordinary
one-function work still needs explicit commit approval. Preserve original scope,
pins and consumed bounds; refresh only at safe checkpoints, never during pinned
transactions. Review payload includes relevant source/diffs/instructions/metadata/
original bytes, never credentials or unrelated media.

Use actual session tools. No shell/MCP/wrapper Codex launch, model SDK/API, detached
runner or substitute Pi process. Missing host capability blocks dependent gates;
worker output cannot self-accept. Ordinary capacity retries must retain original
bounds; an approval denial is not a capacity failure.

Resolve effective compiler/flags before native work: attached function settings,
then `BOF3_OBJCOMPILER_`/`BOF3_OBJFLAGS_` in
`config/compiler/object-flags.cmake`, then project defaults. Managed variants live
in `config/compiler/variants.json`; generated compile database and `bin/cc` carry
selection. Grouped functions require compatible effective profiles. Changing
execution route never changes compiler/flags or substitutes host GCC.

Native status fingerprints use the guarded literal include snapshot through `src`,
`include` and `toolchains/psyq/4.7/include`. Consumed headers and negative lookups
bind every claimed source, support source and header. Effective translation-unit
settings also bind `-include` and `-imacros` operands and their literal dependencies.
Missing forced inputs, changed compiler configuration, unsupported search settings,
directives or header mappings, and unresolved includes refuse cached inspection.
Native comparisons capture literal transitive headers, forced inputs and negative
lookups, and reject changed inputs during the comparison. Unsupported include
search settings refuse cached inspection. These captures do not establish complete
active preprocessing or compiler-input closure.

Path-watch refusals retain the first refusing event's registered directory paths,
escaped entry bytes, watch ID, mask and cookie. Freshness guards remain effective.
These fields identify the observed event, not its writer or a historical cause.

CLI adapters, lift gates and decompilation comparisons propagate
`ProcessCleanupError` unchanged. Unconfirmed cleanup stops retries, fallback
comparisons and later members. Keep POST and owned recovery until child
termination is established.

Grouped native comparisons use current explicit target claims, complete attached
metadata, reviewed Splat ranges, map bindings and effective compiler settings.
They compile the whole source and compare every member at its original placement.
A differing neighbor fails the selected check. No preservation-routing environment
or transaction record is needed. The concern skill retains PRE and proves that
source movement preserves established compiler settings.

Initialized sections require compatible reviewed manifest placements and complete
linked-byte comparison. Unsupported BSS or computed jumps remain unavailable.
Guarded absolute jump tables require a leading load-delay nop, an unsigned bound,
at most 4,096 entries in reviewed readonly data, and targets within the complete
function. Preserve canonical map bindings and complete literal/forced dependencies.
Grouped results bypass ordinary batch-object and cached-status reuse. Current
checks do not provide semantic approval or persistent reuse authority.

Shared CMake configuration retries newly observed race signatures under its
existing lock. A recurring signature, nontransient error or unconfirmed cleanup
propagates unchanged. Follow shared [editing and recovery](editing-recovery.md)
for owned restoration after confirmed writer termination.

Ordinary status fingerprints watch compiler configuration throughout capture and
reject changes even when the original bytes or absence are restored. Literal and
forced dependency checks retain their separate freshness guards.

Ordinary cache keys also bind bounded helper inputs, comparison tools and the
actual bootstrap's stage recipes and environment digests. `bin/cc --bof3-inspect`
uses the execution planner without compiling. Program lookup watches remain live
through comparison and insertion; source, target and tool identities are rechecked
before insertion. Missing or unsupported identities disable lookup and insertion,
while fresh comparisons remain available. Program observations retain
`complete:false`; Python startup, effective runtime selection and full preprocessing
closure remain unproven.

Maspsx defaults to the project interpreter and preserves explicit
`MASPSX_PYTHON` overrides. Tagged local bytecode candidates bind the stage's
optimization setting only when its absolute interpreter matches the captured
supervisor identity and hash. Unqualified interpreters, cache prefixes and
unsupported optimization settings disable ordinary cache reuse.

## Payload delivery

Use `bin/harness build payload TARGET --output-dir out/NEW_DIRECTORY --json`
for an original-based game file. The output directory must be new. This builds
the target's claims and captures fresh exact code and reviewed initialized data
through the native comparison owner. Stored progress alone never qualifies bytes.
Require a nonempty compiled contribution and inspect `report.json` for complete
compiled/retained intervals and whole-file equality. Differing sources retain
original bytes; a group contributes only when every member and its placed data
match. Malformed metadata or unsupported required placement fails delivery.

`payload.bin` preserves the complete shipped executable header or resident entry.
For EMI targets, `archive.EMI` preserves the original archive through the Rust
entry-replacement owner; `entry.bin` verifies the selected slot by extraction.
Require both whole-archive and selected-entry equality. Inputs remain unchanged.
Failure may retain diagnostics but never publishes a success `report.json`.
Hybrid coverage does not establish source-only reconstruction or runtime acceptance.

## Host capability

Canonical driver, `cpp`, `cc1` are static i386 ELF. Known Codex sandbox failure is
`SIGSYS`, shell exit 159, even for `gcc --version`; nested `bwrap` cannot remove
inherited syscall restrictions. This is capability failure, not C evidence.

On that verified host/compiler, parent requests exact bounded native gate through
exposed reviewed escalation before baseline compilation. Where `exec_command`
exists, use `sandbox_permissions: "require_escalated"`. Do not invent this API on
another host. Prefer pinned diagnosis/audit; direct scoped diff/byte gates need
same reviewed capability. Unavailable worker returns `unverified`, null score.
Different host/compiler: establish capability once. Python inspection stays
sandboxed. Standing authorization removes extra conversational checkpoint, not
per-action tool approval. Denial/unavailability blocks gate; continue unaffected work.

Diagnosis/audit inner installed `bwrap` keeps root/source/Git/evidence read-only,
separates network/namespaces, permits generated build/comparison/binding/Splat
outputs and fresh scratch, masks home Codex/Pi directories. Outer restrictions
still apply. No install, self-elevation, permission edits or alternate wrapper
after denial. This is cooperative confinement, not protection against privileged
writers/hostile aliases; other credential locations are not inventoried.
