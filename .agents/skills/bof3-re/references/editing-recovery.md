# Editing and recovery

The selected concern skill owns direct edits. Its authorization names targets,
functions and paths; evidence alone grants no wider scope. Harness list/check
commands report facts and mechanical results, never semantic approval.

## Before editing

1. Inspect current source, map, layout, manifest, headers and affected consumers.
   Resolve identity through target claims and attached function metadata. Preserve
   the complete finite, aligned reviewed original range for every member.
2. Record the dirty baseline and preserve raw index bytes and identity. Retain PRE
   contents, existence, relevant inode/symlink/hardlink identities and ownership
   for explicit changed paths only, including moved or deleted files. Keep adopted
   dirty content in PRE. Do not snapshot clean trees or dependencies.
3. Record current native results and effective build profiles for affected
   functions. Preserve exacts and unselected partials. Selected reconstruction
   partials require independently reviewed expected POST results, no decrease in
   matching instructions, no greater absolute size difference and semantic review
   of every changed instruction. A higher percentage alone proves nothing.
4. Serialize conflicting file and build-output writers. Confirm real process and
   lease ownership; an old lock or receipt does not prove a live writer. Follow
   [native execution](native-execution.md) for host, resource and cleanup bounds.

## Edit and verify

Edit only authorized files with native tools. Keep complete member metadata,
claims, declarations, maps and layout consistent. Inspect existing types and
macros before adding one. Ground names, layouts and useful grouping in original
behavior and consumers, not lexical similarity or an analyzer guess.

Run the concern's current check and required live byte gate over the complete
affected consumer set. Shared header edits cover all owning targets. Check every
grouped record by target and address; measured original size must equal its
reviewed size. Check required placement, initialized data, BSS and bindings.
Missing native or consumer coverage blocks acceptance.

Update only the selected function's progress after current measurement, then
check the edited metadata. Exact means complete byte equality, match 100 and
residual none. Partial and unavailable results retain honest residuals. Authored
tags and caches cannot replace live or semantic acceptance. Obtain required
independent review; self-review is not independent evidence.

## Failure and continuation

After failed comparison, drift, cancellation or review, confirm all owned native
writers have terminated before restoration. Restore only owned PRE contents,
existence and file identities; remove only files created by this edit. Preserve
unrelated work and index bytes. Verify restored state and required native results
before starting another writer.

Uncertain cleanup or restoration stops mutation. Retain PRE, POST, actual handles
and error evidence, and report the unresolved condition. Do not reset the tree,
adopt POST as a new baseline, retry an unchanged failure, or discard historical
attempts. An old transaction receipt does not require keeping its executor.

Report verified scope, actual checks, review and unresolved obligations. A scoped
success does not close a target or campaign. Frozen member sets, bounded mission
limits and unfinished recovery obligations remain binding without ranked accounts
or application envelopes.
