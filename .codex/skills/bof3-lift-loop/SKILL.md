# BOF3 Lift Loop

Start at [docs/INDEX.md](../../../docs/INDEX.md) and the
[current plan correction](../../../docs/plans/autonomous-bof3-decompilation.md#current-skill-only-operator-correction).
This instructional skill is the operator, not a script or background scheduler.
The goal is 100% 1:1 human-readable BOF3 source: faithful functions, supported
names, clean types and useful C89 macros implemented and independently accepted.
Finite missions bound execution, not that whole-game goal.

## Session and ownership

- Delegate, observe and close agents only through tools actually exposed by the
  active session. Never invoke `codex`, a model SDK/API, Pi runner or detached
  substitute through shell, Python, MCP or a wrapper. Workers do not spawn another
  orchestration layer.
- Inspect host capability before promising parallelism or independent review.
  If delegation is absent, continue safe local inspection/tooling and report the
  missing capability. Never invent worker IDs or count self-review as independent.
- Parallelize independent read-only scouting/reviews. Serialize writes in this
  checkout, including shared headers/maps, report sets, refreshes and target build
  outputs. Disjoint selectors alone do not establish independence. Do not discard
  or stage unrelated dirty work to manufacture clean worktree isolation.
- Parent refreshes/reviews and feature commits have standing authority. Preserve
  frozen evidence; no push, installs, permission weakening or retries around denial.

## Mission protocol

Freeze a finite queue and original time/attempt/repair limits before delegation.
Retain current owner inputs and external pins; never reset consumption on resume
or silently replace the frozen five-entry pilot. The active session/selected plan
owns queue dispositions; existing owner artifacts are evidence, not another
campaign database or model-launch controller.

| Handoff field | Required content |
| --- | --- |
| Identity | Unique mission/stage; target-qualified selector or owner opportunity ID; full membership/consumers |
| Route | One skill and explicit mode; predecessor results and dependencies |
| Scope | Read/write role, exact allowed paths, shared inputs/exclusions and adopted dirty baseline |
| Evidence | Original bytes/load/layout; current source/map/index/report pins; reviewed prerequisites |
| Bounds | Original deadline and remaining attempts/repairs; count delegation before issuing it |
| Outcome | Required checks, acceptance/no-op evidence, rollback authority and stop conditions |

Results bind the actual session/tool handle, mission/selector, changed paths/content
pins, commands with real outcomes, evidence, findings and a proposed `accepted`,
`no-op`, `repair`, `blocked` or `deferred` disposition. Writer proposals never grant
parent acceptance. Missing, stale, malformed, failed or timed-out output cannot
advance a successor. Unmeasured native outcomes remain `unverified`/null; command
exit zero alone does not establish fidelity.

## Operator stages

1. **Reconcile:** inspect current worktree and actual handles. Skip accepted work
   only after its owner verifies current acceptance. Uncertain application/cleanup
   stops writes for guarded recovery; retain original bounds.
2. **Select/scout:** use fresh target-qualified opportunities and original bytes.
   Exclude duplicates, accepted/owned work and unresolved shared effects. Independent
   evidence missions may run in parallel within the frozen scope.
3. **Lift — `$bof3-re`:** one function, explicit source/header/map paths, pre-edit
   diagnosis, clean C89, original-byte proof and truthful status. Native checks and
   rollback obligations remain with the domain owner.
4. **Review:** a distinct active-session reviewer inspects actual changed content,
   original instructions and calling/representation semantics, then runs applicable
   scoped checks. Validation may create generated artifacts, never authored edits.
   Parent resolves unavailable local native checks; byte equality cannot replace
   unresolved semantic review.
5. **Name — `$bof3-naming`:** keep opportunity/evidence/audit/transaction authority
   separate. Reuse still-valid target evidence instead of auditing every target per
   function. Preserve storage/ABI/address identity. Selected-row success never
   replaces unfiltered target `complete:true` closure or separate approval.
6. **Types — `$bof3-types`:** prove widths, signedness, fields, layout and ownership;
   implement useful representations through reviewed transactions. Shared promotion
   retains private-proof/common-state gates. Unknown is not a justified no-op.
7. **Macros — `$bof3-macros`:** pin this mission's instruction floor and top-N;
   require at least four uses, size-first ranking and the human-value filter.
   Review evaluation count, side effects, precedence, conversions, aliasing,
   volatility and every consumer. Implement supported byte-safe abstractions;
   retain rejection/defer reasons rather than manufacturing macros.
8. **Finalize:** independently review the combined source; run native/domain gates
   and verify current envelopes. Naming/type/macro no-ops require evidence. Route
   necessary documentation/reference repair through `$bof3-docs`.
9. **Account/continue:** parent accepts only the exact reviewed/verified scope.
   Account every queue member, preserve frozen evidence, refresh affected snapshots/
   index at safe checkpoints and requery consumers. Commit completed owned work
   only, then continue eligible missions within original bounds; no push.

## Tooling, stop and resume

Harness commands are deterministic tools, never agent launchers. Use the domain
skills' existing helpers/CLIs. `bin/agent-run diagnose` and `audit` only capture/check
bounded lift missions; read their help/contracts before constructing pinned inputs.
Local compiler subprocesses and existing supervision remain allowed, not Codex or
model subprocesses. Never refresh inputs during an active pinned transaction.
Before baseline compilation, follow the [native compiler execution route](../../../docs/agents/codex.md#native-compiler-execution):
the known i386/SIGSYS host needs a reviewed, scoped parent-native tool call, not
another sandboxed build or a sandbox-policy change. Missing approval blocks native
gates; workers report unverified and retain original bounds.

Poll the same real handle after observation timeout. Stored PIDs, elapsed time,
files and a free lease do not establish termination. On actual interruption retain
POST/PRE/evidence and consumption; establish writer termination/exclusion before
owner recovery inspection/authorization. Never blindly reapply or restore unrelated
work. A missing host handle requires current-state inspection and an honest blocker,
not recreation through a CLI.

On exhausted bounds, close actual handles and hand off unfinished work without
shrinking the goal. Completion requires whole-game coverage, 1:1 fidelity, human
semantic naming/type/macro acceptance, all plan/queue obligations and real recovery/
parallel-stage evidence. Tool presence, fixtures, green tests, one exact function
or a fully accounted blocked queue cannot prove the end goal.
