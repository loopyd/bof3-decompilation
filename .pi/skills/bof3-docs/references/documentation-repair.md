# Documentation repair

## Scope and authority

Caller names existing authored Markdown. Legacy `bin/harness agent context cleanup
docs PATHS...` supports `docs/`, `AGENTS.md`, `README.md` only. Broader explicit scopes
use native tools under [document contract](document-contract.md).
Resolve claims to implementation/configuration/specification/policy owner or supplied
planning input; generated `out/` and analyzer prose grant no authority. Correct/remove
stale lift counts, transient rankings, disposable snapshots, duplicate claims and
dead links. Preserve history/changelogs.

Place operative protocols and reusable knowledge in relevant skill references;
user-facing explanations remain documentation, scoped work remains caller-owned. Do not relocate files, refactor source, invent policy, execute a plan, or turn a docs repair into naming, lifting, matching, or analysis work.

## Procedure

1. Modified candidate overlap blocks unless parent explicitly adopted edit.
2. Recursively inspect the caller-named paths and resolve each disputed claim to its direct owner.
3. Repair stale claim/broken link only. Preserve unrelated wording and valid history.
4. Resolve every edited link, grep for the stale claim, run focused documentation tests when present, and run `git diff --check`.
5. Report path, owning contract, evidence, smallest repair, validation, and any item requiring human approval. If authority is missing or conflicting, make no speculative edit and name the smallest unblocking decision.
